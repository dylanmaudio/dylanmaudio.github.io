//  Which frame rate?

Use the rate the rest of the show uses.

Timecode only works if everything reading it agrees on the frame rate, so ask the lighting, video or show-control department before you choose. If nobody has decided yet, the usual choices are below.

25 — Europe, the UK, Australia and other PAL regions.

The default for live shows and video in 50 Hz countries.

30 — audio and lighting shows elsewhere.

Common when there is no video to match. Most lighting consoles and media servers take it.

29.97 drop-frame — NTSC video and broadcast.

Matches 29.97 fps video and keeps the timecode in step with the clock on the wall. Non-drop 29.97 counts every frame instead, so an hour of it takes 3.6 seconds longer than an hour.

24 and 23.976 — film and cinema cameras.

When the show is cut to footage shot at those rates.

//  Using it in a playback session

  1. Unzip it.

    Double-click the zip. The WAV inside is mono, 16-bit, and about 350 MB for the hour.

  2. Match the session’s sample rate.

    Take the 48 kHz file for a 48 kHz session and the 44.1 kHz file for a 44.1 kHz one, so nothing resamples the timecode on the way out.

  3. Put it on its own track, with nothing on it.

    No effects, no fades, no time-stretch — in Ableton Live, switch Warp off for the clip. Line up 00:00:00:00 with the start of the show, or wherever the timecode should begin.

  4. Send that track to its own output.

    A dedicated interface output, at unity, not summed with anything else. The file peaks at −18 dBFS, about 0 dBu on most interfaces — a level timecode readers are happy with.

//  Questions

Are they really free?

Yes. No sign-up, no email, no watermark. Use them in any show, paid or not.

Why a zip?

An hour of WAV is about 350 MB. Timecode is a very regular signal, so it zips to a few MB; double-click to get the WAV back.

Why do the 23.976 and 29.97 non-drop files run 3.6 seconds over the hour?

Each file holds one hour of timecode, 00:00:00:00 up to 01:00:00:00. At those rates every frame is counted but the frames are slightly longer than the rate’s name suggests, so an hour of timecode takes an hour and 3.6 seconds. Drop-frame 29.97 skips frame numbers to stay on the clock instead.

Are the files any good?

They come from the encoder inside Time Code Tool, and every file is read back and decoded frame by frame before it goes up here: all frames present, in order, with the right drop-frame flag.

I need a different start time, length or level.

Time Code Tool renders LTC WAVs with any start, length, frame rate, sample rate, bit depth and level. Its free trial does it too.

My timecode reader won’t lock.

Check the frame rate matches, the track isn’t time-stretched or processed, and the output isn’t summed with anything else. If it still drops frames, Time Code Tool shows exactly what is arriving: the detected rate, and every missed, misread or jumped frame.
